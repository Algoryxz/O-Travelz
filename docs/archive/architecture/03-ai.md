# AI Architecture

Location: `backend/app/ai/`.

## Role

The AI layer does three things, and only these three:

1. **Understand intent** — turn free-text user input into structured constraints
   (`{interests: [...], pace: "relaxed", budget_transport_per_day: 300, start: "Hotel X",
   days: 2, mobility: "no long walks"}`), using a defined schema
   (`backend/app/ai/schemas.py`).
2. **Orchestrate tools** — call deterministic backend services (ranking, itinerary
   builder, transport planner) via a fixed tool-calling interface
   (`backend/app/ai/tools/`). It cannot answer factual questions itself; it must call a
   tool that queries the DB/services.
3. **Explain and converse** — turn structured tool output into readable text, and handle
   follow-up requests by re-deriving structured constraints and re-calling tools (never
   by hand-editing the itinerary text itself).

## Hard rule

The AI layer's system prompt must explicitly forbid stating any specific fact (place
name, address, opening hour, fare, bus number, travel time) that did not come from a tool
result in the current turn. If a tool doesn't have an answer, the AI says so — it does
not fill the gap.

## Tools exposed to the AI (contract, not implementation)

- `search_places(interests, area, constraints) -> Place[]`
- `build_itinerary(constraints, candidate_places) -> Itinerary` (calls ranking +
  itinerary generation internally)
- `plan_transport_hop(from_place, to_place, constraints) -> TransportHop`
- `get_place_details(place_id) -> Place`
- `get_provider_status(provider_id) -> {data_tier, notes}` — so AI can honestly caveat
  ("Mo Bus schedule is fixed-route/approximate frequency, not live-tracked")

Each tool wraps a deterministic backend service — the AI never bypasses these to query
the DB directly.

## What the AI is explicitly NOT responsible for

- Ranking/scoring places (deterministic — see `backend/app/services/ranking/`)
- Sequencing stops or choosing transport modes (deterministic — see
  `backend/app/services/itinerary/` and `backend/app/transport/`)
- Computing distances, durations, fares (deterministic)
- Geometry/map data (deterministic — `backend/app/geospatial/`)

## Testing implication

Because AI calls are tool-mediated, tests can record fixed tool-call transcripts and
assert (a) the AI called the right tools with the right structured args, and (b) its
final text doesn't contain facts absent from the tool outputs. This keeps AI tests
deterministic in CI without needing live model calls.
